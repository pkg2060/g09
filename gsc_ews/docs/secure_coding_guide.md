# 시큐어 코딩 지침

사용자가 제공한 EWS 개발 지침이다. 새 코드와 변경 코드에 적용한다.

시큐어코딩 가이드라인
EWS Pipeline은 고객사에서 제공한 Python 시큐어코딩 가이드를 기준으로 개발하며, 전체 보안 항목 중 현재 시스템 구조와 직접적으로 연관되는 항목을 우선 적용한다. 특히 EWS는 외부 시계열 데이터와 Config를 입력받고, 학습된 Model을 Load하여 Online 환경에서 지속적으로 추론하며 결과를 파일 또는 DB에 저장하는 구조이므로, 입력값 검증, 파일 및 경로 접근 통제, 중요정보 관리, 예외 처리, 자원 관리, 외부 패키지 관리를 주요 보안 설계 대상으로 한다

입력 데이터 및 Config 검증

RTDB/API, CSV 및 Config 등 외부에서 유입되는 데이터는 신뢰된 값이라고 가정하지 않고 형식, 타입, 범위 및 필수 항목을 검증한 후 사용한다.

특히 window_size, threshold, 모델명, 파일 경로 등 Pipeline 동작을 결정하는 값에 대해 허용 범위를 정의한다.

외부 입력을 eval(), exec() 등 동적 코드 실행 함수에 전달하지 않는다.

가이드에서는 검증되지 않은 입력값에 의한 코드 삽입과 보안기능 우회를 주요 보안약점으로 정의한다.

파일 경로 및 저장 자원 관리

data/, models/, outputs/, Config 등의 파일 경로를 임의 외부 입력으로 직접 생성하지 않고 사전에 정의된 경로 또는 허용 범위 내에서 사용한다.

../ 등의 경로 조작을 통한 비인가 파일 접근이 발생하지 않도록 입력 경로를 검증한다.

모델, Config 및 결과 파일에는 필요한 최소 권한만 부여한다.

이는 가이드의 경로 조작 및 자원 삽입, 중요한 자원에 대한 잘못된 권한 설정에 해당한다.

중요정보와 환경 설정 분리

DB/API 인증정보, Access Key, Password 등의 중요정보를 Python Source Code 또는 주석에 하드코딩하지 않는다.

일반 모델 Hyperparameter는 Config에서 관리하되, 인증정보와 같은 Secret은 Config와도 분리하여 환경변수 또는 별도의 보안 저장소를 통해 관리한다.

가이드는 하드코드된 중요정보 및 주석문 내 중요정보 노출을 별도 보안약점으로 규정한다.

예외 처리 및 정보 노출 방지

Data Loading, Model Loading, Inference, Result Save 등 I/O가 발생하는 주요 단계에는 예외 처리를 적용한다.

except:와 같이 모든 오류를 무조건 무시하지 않고 발생 가능한 예외를 구체적으로 처리하며, 오류 발생 후 Pipeline이 잘못된 상태로 계속 실행되지 않도록 한다.

운영 환경에서는 Stack Trace, 내부 경로, Config 값 등 시스템 내부정보가 외부 출력이나 로그에 불필요하게 노출되지 않도록 한다.

가이드에서도 오류 메시지 정보노출, 오류상황 대응 부재, 부적절한 예외처리를 각각 구분하여 관리하고 있다.

파일·DB·네트워크 자원 해제

파일, DB Connection, Socket 등 외부 자원은 사용 후 반드시 반환하도록 하며 가능한 경우 with 등의 Context Manager를 활용한다.

향후 Online Pipeline이 장시간 반복 실행되므로 자원 미반환이 누적되지 않도록 설계한다.

가이드에서는 이를 부적절한 자원 해제에 따른 자원 고갈 위험으로 정의한다.

Online 실행 및 공유 자원 제어

Online Mode에서 동일 파일, Output DB 또는 공유 상태에 여러 실행 흐름이 동시에 접근할 가능성이 있는 경우 동시 접근을 통제한다.

특히 Threshold/Alarm 상태, 실시간 Output 저장 등 상태가 유지되는 자원은 경쟁조건이 발생하지 않도록 고려한다.

장시간 반복되는 Online Loop에는 정상적인 종료 및 오류 발생 시 탈출 조건을 명확히 정의한다.

이는 가이드의 경쟁조건(TOCTOU) 및 종료되지 않는 반복문과 직접 연관된다.

모델 및 외부 데이터의 안전한 Load

외부에서 전달되거나 출처가 불명확한 직렬화 객체를 그대로 Load하지 않는다.

모델 파일을 외부에서 수신하거나 배포하는 구조가 추가될 경우 출처 및 무결성을 검증한 파일만 사용한다.

특히 Python pickle 계열의 역직렬화는 임의 코드 실행 가능성이 있으므로 신뢰 가능한 모델 Artifact만 Load하도록 한다.

가이드에서도 신뢰할 수 없는 데이터의 역직렬화와 무결성 검사 없는 코드 다운로드를 주요 보안약점으로 다룬다.

외부 패키지 및 API 관리

PyTorch, PyTorch Lightning, SHAP 등 외부 Python Package는 필요성이 확인된 라이브러리만 사용하고 버전을 명시적으로 관리한다.

사용하지 않는 Package의 추가를 최소화하고, 알려진 취약점이 존재하는 버전은 사용하지 않는다.

requirements.txt 등을 통해 사용 Package와 Version을 추적 가능하도록 관리한다.

가이드에서는 외부 Package의 유지관리 상태와 알려진 취약점을 확인하고, 장기적으로 SBOM을 통해 의존성을 관리할 것을 제시한다.
